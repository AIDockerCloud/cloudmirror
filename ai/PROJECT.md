# 项目定位与目标 (PROJECT.md)

## 1. 项目基本信息
- **项目名称**：cloudmirror (核心实现为 `bw_sync.py`)
- **定位**：面向自托管密码管理场景的 NodeWarden ↔ Vaultwarden 个人保险库双向对比与安全同步系统。
- **目标用户**：同时自建两套 Bitwarden 兼容服务端（如 Cloudflare 上的 NodeWarden 与家庭网络/私有云 Olares/VPS 上的 Vaultwarden）且需要高容错双向冗余备份的自托管开发者与高级用户。

## 2. 核心宗旨与痛点解决
密码数据属于个人资产中安全性与可靠性要求最高的资产。多端同步中普遍存在以下核心痛点：
1. **自动覆盖导致数据损坏**：简单的双向同步工具常因单端更新或时钟不一致误判版本先后，粗暴覆盖导致密码被篡改；
2. **误删传播与灾难性清空**：单侧误操作、数据库意外清空或网络拉取失败若自动传播删除指令，会导致双端数据同归于尽；
3. **明文与凭据泄露风险**：脚本若在磁盘或日志留存主密码与解密凭据，将带来严重安全隐患；
4. **外部复杂依赖膨胀**：过度依赖复杂的第三方库或运行时，容易产生供应链安全隐患（如 npm 恶意包投毒）。

**cloudmirror 的核心原则**：
- **只增不改不删**：只同步新增条目；遇到内容变更一律保留两边原件并各自生成带日期的冲突副本（人工裁决）；遇到单侧条目消失一律仅记墓碑报警、绝不联动删除；
- **零外部 pip 依赖**：纯 Python 3 标准库单文件实现，配合固定哈希校验的官方 Bitwarden CLI 二进制；
- **凭据隔离**：主密码和解密数据绝不落盘，双端运行配置与 session 目录物理隔离，运行完毕自动锁定。

## 3. 边界与硬约束 (Scope & Hard Constraints)

### 范围 (Scope)
- **支持条目类型**：个人保险库条目（登录项、安全笔记、安全卡片、身份信息、SSH 密钥）以及文件夹映射结构；
- **配对机制**：结合状态映射表 (`bw-sync-state.json`) 与自然键（条目类型 + 名称 + 用户名/标识）配对；
- **判等机制**：规范化去除易变元数据后通过 SHA-256 哈希判等；
- **运行模式**：
  - 本地 Win11/Linux 手动运行（交互式输入主密码或终端环境变量）；
  - 容器化定时任务（Docker + Docker Compose，通过 `docker compose run --rm` 一次性执行后退出）；
  - 离线逻辑完整自测套件 (`--selftest`)。

### 非目标 (Non-Goals)
- **v1 不自动搬迁附件**：检测到附件仅在报告中点名警告，由用户手动迁移；
- **v1 不搬迁 Passkey (FIDO2 凭证)**：登录条目同步时自动剥离 `fido2Credentials`，因为 Passkey 绑定各端独立账号公私钥体系；
- **不支持组织/集合与 Send 同步**：仅支持个人保险库；组织条目与 Send 直接跳过；
- **不自动传播硬删除**：永远不自动抹除条目。如需真删，必须在两边服务端手动删除；
- **不常驻后台常驻进程**：非长驻守护进程，作为一次性定时执行命令（如宿主机 cron）。

### 硬约束 (Hard Constraints)
1. **绝不破坏原件**：在任何冲突与歧义情况下，绝不得自动覆盖或覆盖写入已存在的原条目；
2. **明文凭据绝不落盘**：主密码、解密保险库明文密码绝对禁止写入配置文件、日志输出、Git 版本库或构建镜像中；
3. **独立运行隔离**：两端的 Bitwarden CLI 登录态必须通过独立的 `BITWARDENCLI_APPDATA_DIR` 目录物理隔离；
4. **Markdown 协同权威**：工程上下文管理遵循 PCMP v2.2 规范，以 `ai/` 下 Markdown 文件为权威真源。
